# Current integration limits

Puente does not currently attempt a payment. The official x402 material reviewed for this build documents EVM, Solana, and Algorand examples, but does not establish a supported Stellar mechanism for Pollar. The purchase endpoint therefore returns `503` before any signing or settlement call.

Pollar `@pollar/core` and `@pollar/react` are pinned at `0.10.1`. The worker can connect a worker-controlled wallet and open the provider ramp UI when a valid publishable key is configured. Puente does not create payout quotes, submit payouts, or mark BOB received because the provider contracts for those operations have not been verified.

The African funding leg remains a manual adapter contract. No NGN confirmation, liquidity release, stablecoin delivery, or BOB receipt is inferred or generated by the application.

Direct worker payment is prepayment, not escrow. Once a supported payment adapter is connected, Puente cannot claw funds back from a worker wallet. Refunds require a separate worker-authorized transfer, and paying a replacement worker requires fresh buyer authorization.
